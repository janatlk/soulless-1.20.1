# MODLOG — Soulless (Minecraft 1.20.1 Forge)

## Intake
- Game: Minecraft Java 1.20.1, Forge 47.4.23. Dev/testing via `gradlew runClient` (own `run/` dir, user worlds untouched).
- Idea: legendary two-handed sword "Soul Forged" / «Кованная душа» — big custom blocky 3D model (GeckoLib),
  permanent purple flame, R-key SLAM ability (huge AoE damage + temporary visual block cracks),
  hits apply "Soul Curse" (purple flame DoT, slow, no jumping, replaces vanilla fire, no stacking),
  crafted from 4 new materials (no source yet — future bosses). Full tooltip RU + EN.

## Route
Loader API (Forge) + GeckoLib 4.8.4 for the animated item model. No mixins.
- Two-handed hold / slam arm pose: Forge `HumanoidModel.ArmPose.create(..., twoHanded=true, IArmPoseTransformer)`
  returned from `IClientItemExtensions#getArmPose`.
- Block cracks: `ServerLevel#destroyBlockProgress(fakeBreakerId, pos, stage)` with unique negative ids, decayed back to -1.
  Purely visual; blocks are never broken.
- Purple flame on mobs: mob effects of non-player entities are not synced to clients, so a custom S2C packet
  keeps a client map entityId -> expiry; `RenderLivingEvent.Post` draws the flame like vanilla `renderFlame`.

## Gotchas
1. GeckoLib (fg.deobf) crashes in dev with "Critical injection failure ... TextureManagerMixin": add
   `mixin.env.remapRefMap=true` + `mixin.env.refMapRemappingFile=build/createSrgToMcp/output.srg` to runs.
2. `HumanoidModel.ArmPose.create` lazily at first render -> AIOOBE in `poseRightArm` (enum switch map built
   already). Create the pose during mod construction (client only).
3. Effect attribute modifiers scale with (amplifier+1); override `getAttributeModifierValue` to keep a flat value.
4. Display transform for a +Y-pointing 3D item held perpendicular to the arm: thirdperson rotation [0, 90, 0].
5. Bedrock geo cube rotation as read by GeckoLib = (-x, -y, +z) of the Java-space rotation.
6. Autotest: set `pauseOnLostFocus=false`, or the integrated server pauses when the window loses focus.
7. GeckoLib 4.8 (1.20.1) does NOT animate a geo texture from an `.mcmeta` strip: UVs get squashed over the whole
   strip. Animate by swapping texture files per frame in `GeoModel#getTextureResource` instead. (Flames were
   later removed at the user's request, so the shipped model uses one static texture.)
8. Glowmask must have exactly the base texture's dimensions or GeckoLib throws on texture registration.
9. 1.20 entities load asynchronously after login: an entity sweep in `PlayerLoggedInEvent` misses them.
10. Full-body poses: `IArmPoseTransformer` runs before vanilla resets `body.xRot`/positions, so lean/flip/kneel
    height go on the pose stack in `RenderPlayerEvent.Pre` (push) / `Post` (pop); legs xRot set in the
    transformer survives.
11. First person: cancel `RenderHandEvent` and call `itemInHandRenderer.renderItem(...)` with your own transforms
    (json first-person display left as identity). With identity, a +Y GeckoLib model stands upright facing the camera.
12. Side camera for screenshots: a client-only invisible ArmorStand via `ClientLevel#putNonPlayerEntity` +
    `Minecraft#setCameraEntity`.
